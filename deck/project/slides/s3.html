  • Portal images

It doesn't touch

  • Documents & Media

Measured: TTFB flat · guest HTML private, no-store 100 % → 0 % · D&M public, max-age=86400 · Set-Cookie still sent

[11:15–14:15 · 3:00] cdn.host.https plus cdn.dynamic.resources.enabled covers theme and module JS and CSS, the combo servlet, ES modules and portal images. It does not touch Documents and Media, Adaptive Media, portlet resource URLs, or page HTML. Documents and Media has its own Cache Control setting. The first change that makes a guest page describable as cacheable is browser.cache.disabled=false, keeping browser.cache.signed.in.disabled=true. Regenerate Adaptive Media for existing content; lazy-load everything except the LCP image. Measured: S3 changes headers, not milliseconds. Where assets do matter is CPU: on a first visit static files were 84 percent of Liferay's CPU until the edge cached them, which is rung 3. TTFB stayed flat, but guest HTML went from 100 percent private, no-store to zero, and the brochure PDF to public, max-age 86400. The Set-Cookie is still there, which is why the edge must strip it. Gotcha found on 2026.Q1: the D&M Cache Control PID is com.liferay.document.library.web.internal.configuration.CacheControlConfiguration; the old PID silently does nothing.
